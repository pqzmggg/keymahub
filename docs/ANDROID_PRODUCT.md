# KemaHub (Android) 제품 기획 (v0.4)

> P0에서 검증된 기술을 실제로 매일 쓸 수 있는 앱으로 만들기 위한 기획.
> v0.2: §12 결정 반영 — **KemaHub**, Android 호스트 + **BLE만**, **단축키 전환**, **유료**, **Play 스토어(우선 비공개 테스트)**.
> v0.3: 단축키 배치 변경(`1` = 이 폰), **단축키 사용자 지정**, **프로필**, **6개 언어**, 첫 실행 시 호스트 모드 권한 자동 요청.
> v0.4: 화면 개편(메인 = 호스팅 on/off + 프로필 목록, ⋮ 메뉴에 기기 관리·설정), **페어링 모드**, 기기 연결 해제·별칭·마지막 사용, 언어·테마 설정, **프로필 활성화 조건(시간·장소)과 우선순위**.
> 코드: `android/kemahub` (PoC 콘솔은 `android/app` 에 그대로 둔다).

## 0. v1.0 확정 사항 (2026-09-23)

| 항목 | 결정 |
|---|---|
| 앱 이름 | **KemaHub** (패키지명 `com.kemahub.app` 가정 — 첫 업로드 전 확정, 이후 변경 불가) |
| 범위 | **Android 호스트만**: 폰에 연결한 키보드·마우스 → **BLE HID** → 대상 기기 (대상에 설치 없음) |
| 입력 받기 | 접근성 서비스(키보드) + 포인터 캡처(마우스). **Shizuku·클래식 블루투스·리시버 모드는 v1.0에서 제외** |
| 전환 | 단축키만. **숫자 고정**: `1` = 이 폰, `2`~`9`, `0` = 기기 1~9. 기본 보조키 **Shift+Alt** |
| 단축키 | **보조키 조합만 앱 설정에서 변경**(Ctrl/Alt/Shift/Meta, Ctrl·Alt·Meta 중 하나 필수). 모든 프로필 공통. 대상 조작 중 단축키를 누르면 대상에 F24를 한 번 보내 Windows의 Alt+Shift 언어 전환·Alt 메뉴 활성화를 막음 |
| 프로필 | 호스팅 설정 = 프로필 (어느 기기를 어느 단축키에 둘지 + 단축키 조합). 여러 개 만들고 전환 (예: 회사/집). 새 프로필은 현재 것을 복사 |
| 기기 배정 | 처음 연결된 기기는 **현재 프로필**의 빈 리시버 자리에 자동 배정. 기기 목록(이름)은 모든 프로필 공통 |
| 화면 | 메인: **호스팅 on/off 스위치 + 프로필 목록(우선순위 순)**. ⋮ 메뉴: 기기 관리, 설정, 진단. 프로필을 누르면 조건·단축키 편집 |
| 프로필 조건 | **시간**(요일 + 시작~종료, 자정 넘김 가능, 같으면 하루 종일) / **장소**(현재 위치 + 반경 100 m~2 km) / 둘 다(모두 만족) / 없음(항상) |
| 우선순위 | 목록 위쪽이 높음, 행 앞의 ☰를 끌어서 순서 변경. **조건이 맞는 프로필 중 가장 위의 것** 사용. **맞는 게 없으면 마지막으로 직접 "활성화"한 프로필** 사용(조건 없는 프로필은 이렇게만 쓰임). 조건이 맞는 중에 다른 프로필을 활성화하면 조건 상황이 바뀔 때까지 그 프로필 우선("자동으로 돌아가기"로 해제). 목록 각 행 끝에 **활성화·편집** 버튼 |
| 장소 확인 | 장소 조건이 있고 위치 권한이 있을 때만, 호스팅 중에 저전력 위치 업데이트(약 3분/100 m). 포그라운드 서비스 유형 `location` 추가 → **Play에 위치 포그라운드 서비스 신고 필요** |
| 기기 관리 | **페어링 모드**(3분): 켜져 있을 때만 새 기기 페어링 허용·이름 광고, 꺼져 있으면 페어링된 기기만 연결. 기기별 **별칭**, **마지막 사용**(연결·전환·해제 시각), **연결 해제**(재연결 거부, "연결 허용"으로 복구), **삭제**(페어링 해제 시도 + 모든 프로필에서 제거) |
| 설정 | 언어(시스템/6개 언어, Android 13+는 앱별 언어와 연동), 테마(시스템/밝게/어둡게), 동적 색상(Android 12+), 전환 팝업 표시 |
| 언어 | 영어(기본)·한국어·일본어·중국어(간체)·스페인어·프랑스어. Android 13+ 앱별 언어 설정 지원 |
| 첫 실행 | 호스트 모드 설정 화면에서 **블루투스(근처 기기)·알림 권한을 바로 요청**하고, 이어서 접근성 사전 고지 → 설정 이동. 알림은 권장(없어도 동작) |
| 판매 | 유료 앱 (Play 결제). 앱 내 결제·광고 없음 |
| 배포 | Google Play. 우선 **비공개 테스트 트랙**, 이후 프로덕션 |

## 1. 한 줄 정의

**폰·태블릿에 연결한 키보드·마우스로 옆의 PC와 태블릿까지 조작하는 앱.**
대상 기기에는 아무것도 설치하지 않고 블루투스로 붙이며, 서버도 계정도 없다.

## 2. 사용자와 핵심 시나리오

| # | 시나리오 | 역할 | P0 상태 |
|---|---|---|---|
| S1 | 태블릿 + 블루투스 키보드·마우스로 작업하다가, 옆의 Windows 노트북도 **같은 키보드·마우스**로 조작 | 호스트 | ✅ 검증 |
| S2 | 노트북·데스크톱·iPad를 번갈아 조작 (단축키 한 번에 즉시 전환) | 호스트 | 구현됨, 미검증 |
| S3 | PC 앞에서 일하다가 폰 메시지에 **PC 키보드·마우스로** 답장 | 리시버 | v1.0 제외 (Shizuku + PC 프로그램 필요) |

**하지 않는 것**: 화면 미러링, 파일 전송, 인터넷 너머 원격 조작, 게임용 초저지연.

## 3. 제품 원칙

1. **설치 후 5분 안에 첫 전환.** 필요한 설정만, 필요한 순간에 요청한다.
2. **입력이 지금 어디로 가는지 항상 보인다.** (알림, 전환 순간의 화면 표시)
3. **언제나 빠져나올 수 있다.** 비상 단축키, 대상 끊김 시 자동 복귀, 앱이 죽으면 모든 가로채기 해제.
4. **입력 내용을 저장하거나 외부로 보내지 않는다.** 대상 기기로만 전달.

## 6. 사용자 흐름

### 6.1 첫 실행 (호스트)
```
환영
 → ① 알림 허용 → ② 근처 기기(블루투스) 허용
 → ③ 접근성: 사전 고지(무엇을·왜·저장/전송 안 함) → [동의하고 설정 열기] → 돌아오면 자동 확인
 → ④ 시작 → 첫 대상 추가 (6.2)
 → ⑤ "Ctrl+Alt+1 을 눌러 보세요" → 전환 성공 표시
```
각 단계는 **이미 되어 있으면 건너뛴다.** 중간에 나가도 다음 실행 때 이어서 한다.

### 6.2 대상 추가
- 앱 화면: 대상 OS 선택(Windows / Mac / iPad / Android) → OS별 그림 안내.
  - Windows: 설정 → 블루투스 및 장치 → 장치 추가 → 블루투스 → **이 폰 이름**.
    목록에 없으면 "Bluetooth 장치 검색 = 고급" 안내 (Windows 11 기본 검색이 숨김).
  - 페어링하는 동안 폰의 블루투스 설정 화면을 열지 않도록 안내 (클래식 "휴대폰"으로 잘못 붙는 것 방지).
- 대상이 연결되면 자동으로 목록에 추가되고 이름을 붙이게 한다.

### 6.3 일상 사용
- 앱을 닫아도 상시 알림이 떠 있다: "이 폰 조작 중 / 1 데스크톱 조작 중", 버튼 [중지].
- 기본 `Ctrl+Alt+1`: 이 폰으로, `Ctrl+Alt+2`~`9`, `0`: 리시버 1~9로 (프로필마다 변경 가능). 연결 안 된 자리면 "데스크톱 연결 안 됨" 표시.
- 전환할 때 폰 화면에 잠깐 표시: "→ 1 데스크톱", "← 이 폰".
- 대상이 꺼지거나 멀어지면 자동으로 폰으로 돌아오고 알림으로 알린다.

### 6.4 문제 상황
| 상황 | 앱의 반응 |
|---|---|
| 접근성 서비스가 꺼짐 (시스템이 끄는 경우 포함) | 알림으로 알리고 한 번에 설정으로 이동 |
| 포인터 캡처가 거부됨 | 대체 방식으로 계속 동작 + "폰 포인터도 움직일 수 있음" 안내 |
| 이 기기가 BLE 주변기기 모드를 지원 안 함 | 첫 실행에서 바로 알림 (호환성 표 링크) |
| 대상이 재연결 안 됨 | 대상 화면에 "다시 페어링" 안내 |

## 7. 화면 구성

1. **홈**: 상태 카드(켜짐/꺼짐, 현재 조작 대상), 연결된 대상 목록(활성 표시), 시작/중지.
2. **대상**: 번호·이름·연결 상태, 이름/번호 변경, 삭제, [대상 추가] 가이드.
3. **단축키·프로필**: 슬롯 10개(이 폰 + 리시버 9) 목록에서 기기 배정·단축키 녹화, 프로필 전환·추가·이름 변경·삭제.
4. **권한·진단**: 필요한 권한 체크리스트, 로그 보기.

UI는 Jetpack Compose + Material 3. P0 콘솔 화면은 "개발자 메뉴"로 숨겨 남긴다.

## 8. 백그라운드·배터리

- 호스트가 켜져 있는 동안 Foreground Service(`connectedDevice`) + 상시 알림.
- BLE 광고: 대상이 없을 땐 빠르게, 대상이 준비되면 저전력 (P0에서 구현).
- 배터리 최적화 예외는 첫 실행에서 요청하지 않고, 끊김이 감지될 때 안내 (심사·사용자 거부감 고려).
- 목표: 호스트 켜 둔 채 대기 시 배터리 소모 **시간당 2% 이하** (측정 필요).

## 9. 배포·정책

| 항목 | 내용 |
|---|---|
| **접근성 API (가장 큰 리스크)** | Google Play는 접근성 API를 장애 보조 목적 외로 쓰면 신고·심사가 필요하고 거절 사례가 많다. KemaHub는 "물리 키보드 입력을 다른 기기로 전달"하는 핵심 기능에 필요하므로, 사전 고지·동의 화면과 시연 영상으로 신고한다 (§13). 거절되면 대안을 따로 검토. |
| Play 설치본 | Play에서 설치하면 "제한된 설정" 단계가 없다 (APK 직접 설치에만 해당). |
| Foreground Service 유형 | Play Console에 `connectedDevice` 사용 사유 신고 필요. |
| 개인정보 | 키 입력을 저장·전송하지 않음(대상 기기로만 전달)을 정책 문서에 명시. |

## 10. 품질 기준 (v1.0 출시 조건)

- 설치부터 첫 전환까지 **5분 이내** (처음 쓰는 사람 3명 기준)
- 전환 단축키 → 대상에 입력 도착 **체감 지연 없음** (측정 목표 < 100ms)
- 1시간 연속 사용 중 **끊김 0회, 키가 눌린 채 남는 현상 0회**
- 호환성 표: 폰 3개 제조사(삼성·픽셀·샤오미) × Android 3개 버전 × 대상 3종(Windows 11, macOS, iPadOS)
