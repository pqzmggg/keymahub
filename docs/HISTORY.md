## 1. 목표와 원칙 (2026-09-23, 출발점)

- 키보드·마우스를 Windows / Android / Linux 사이에서 공유한다. **1순위는 Windows ↔ Android.**
- 호스트가 리시버를 등록하고, 조건(단축키 또는 화면 경계)이 충족되면 입력을 해당 기기로 보낸다.
- **서버 없음, 같은 네트워크(가까이 있는 기기)에서만.**
- 한 기기가 호스트·리시버로 모두 등록될 수 있고, 둘 다면 시작할 때 고른다. 백그라운드에서 동작한다.

## 4. Android 호스트 — 방향 결정 과정

1. **"호스트를 블루투스 기기로 인식시킬 수 있나?"**
   - Android는 앱이 블루투스 키보드·마우스 역할을 할 수 있음. Windows는 불가(동글 필요), Linux는 가능.
   - 장점: 대상 기기에 앱 설치 불필요, 암호화는 블루투스 페어링이 담당.
2. **"Shizuku(개발자 옵션) 없이 쓰고 싶다" → "개발자 옵션 작업 자체가 번거롭다"**
   - 개발자 옵션 없이 다른 앱에 진짜 입력을 넣는 방법은 Android에 없음 → 무권한 경로는 접근성 서비스 또는 하드웨어 동글뿐.
3. **결정 (D8)**: Android 호스트 = 블루투스, Android 리시버 = Shizuku.
   호스트 입력원은 **폰에 연결한 실제 키보드·마우스**.

## 6. KeymaHub (Android 제품, 처음 이름 KemaHub) 착수

- 결정: 첫 유료 제품은 **Android 블루투스 허브만**. 이름 KemaHub, Play 스토어 비공개(closed) 배포부터.
- 결정: **단축키만** (`Ctrl+Alt+1~9` = 대상 번호, `Ctrl+Alt+0` = 이 폰). 화면 경계는 뒤로.
- 결정: **BLE(HOGP)만**. 클래식 HID·Shizuku·리시버 모드는 제품에서 제외 (P0 앱에만 남김).
- 구현: 새 모듈 `android/keymahub` (당시 `android/kemahub`, 패키지 `com.kemahub` → 지금 `app.keymahub`, Compose UI). P0에서 검증한 BLE HID·전송 큐·접근성 캡처·포인터 캡처를 옮기고,
  번호 슬롯 라우터(`SlotRouter`)·대상 번호표(`SlotTable`)·포그라운드 서비스·설정 안내(접근성 사전 고지 포함)를 새로 작성.
- 단위 테스트: 슬롯 단축키·전환 시 키 해제 순서·번호 교환·전송 큐.
- 변경 (v0.3): 단축키 배치를 **`1` = 이 폰, `2~9, 0` = 리시버**로 바꾸고 **사용자 지정** 가능하게 함 (조합이 정확히 일치해야 전환, 녹화 중에는 전환 멈춤).
  **프로필**(기기 배정 + 단축키)을 여러 개 두고 전환. **영어·한국어·일본어·중국어·스페인어·프랑스어**.
  첫 실행 시 호스트 모드 권한(블루투스·알림)을 바로 요청하고 접근성 고지로 이어짐.
- 실기기: **Windows로 넘기면 폰 터치가 전혀 안 됨** → 포인터 캡처 오버레이가 화면 전체를 덮는 터치 가능 창이었음.
  1×1, 터치 불가·터치 비모달 창으로 변경. 폰을 터치하면 포커스가 앱으로 가서 캡처가 풀리므로, 마우스를 다시 움직이면 캡처를 되찾음 (Android 14+).

- 변경 (v0.4): 화면 개편 — 메인은 호스팅 스위치 + 프로필 목록, ⋮ 메뉴에 기기 관리·설정.
  **페어링 모드**(켜져 있을 때만 새 기기 허용), 기기 연결 해제(재연결 거부)·별칭·마지막 사용, 언어·테마 설정.
  **프로필 활성화 조건**(시간·장소·둘 다) + 목록 순서 = 우선순위, 수동 고정.

- 변경: 조건에 맞는 프로필이 없으면 **마지막으로 활성화한 프로필** 사용(조건 없는 프로필은 직접 활성화할 때만). 순서는 ☰ 드래그, 행 끝에 활성화·편집 버튼.
- 실기기: Windows 조작 중 폰 가상 키보드가 안 뜸 → 물리 키보드 연결 시 Android가 숨기는 기본 동작. 대상 조작 중에만 접근성 서비스로 "하드 키보드 무시" 표시 모드(Android 10+).

- 변경: 단축키를 프로필·슬롯별 녹화 → **앱 전체 보조키 조합 + 고정 숫자**(기본 Shift+Alt, 1 = 이 폰, 2~9·0 = 기기). Windows에서 Alt+Shift가 언어 전환이라, 전환 시 대상에 F24를 끼워 넣음.

- 변경: 프로필의 **장소 조건을 "연결된 기기" 조건으로 교체**. 지도 선택 요청을 검토하다가, 가까이 오면 자동 재연결되는 BLE 기기가 장소보다 정확하고 위치 권한·Play 위치 신고·지도 키가 필요 없어서 결정.

- 변경: 프로필 **활성화 방식 3가지**(설정): 완전 자동(연결된 배정 기기 수 최다, 기본) / 규칙 기반 자동 / 끄기(수동).

- 변경: **시간 조건 제거**. 규칙 기반 자동은 "고른 기기 연결 시"만. 시간 경계에서 작업 중 전환이 튀고, 기기 조건으로 대부분 충분.

- 변경: 앱 이름 **KemaHub → KeymaHub** (화면·알림·접근성 설명·릴리스 파일명).

- 변경: **앱 아이콘**(키보드·마우스 허브 그림, 적응형·테마 아이콘) 적용. 코드 패키지 `com.kemahub` → **`com.keymahub`**, 앱 ID `com.kemahub.app` → **`com.keymahub.app`**, 모듈 `android/kemahub` → `android/keymahub`, 접근성 서비스 `KeymaAccessibilityService`.
  앱 ID가 바뀌어 기존 설치본과는 별개 앱(설정·페어링 다시). 릴리스 secrets 이름은 `KEYMAHUB_*`(예전 `KEMAHUB_*`도 읽음).
- 변경: 저장소·프로젝트 이름 **keymanc → keymahub** (Rust 크레이트 `keymahub-proto`·`keymahub-keymap`, PoC 앱 패키지 `dev.keymahub.poc`, Gradle 루트 `keymahub-android`, BLE 제조사 이름 `KeymaHub`).
  아이콘 여백은 원본 그림과 같은 비율(그림 폭 = 보이는 아이콘 폭의 약 82%).
- 실기기: 호스팅을 껐다 켜면 **태블릿이 자동으로 다시 붙지 않음** → BLE 키보드는 광고만 하고 연결은 대상이 거는데, 일부 호스트(특히 Android 태블릿)는 키보드 쪽이 끊은 뒤로는 다시 걸지 않음.
  호스팅을 켤 때(그리고 "연결 허용" 때) **폰이 페어링된 기기에 먼저 자동 연결**(백그라운드 대기, 차단한 기기 제외). "연결 해제"는 폰 쪽 연결도 닫아 링크가 실제로 끊기게 함.
- 변경: **P0 테스트 콘솔 앱(`android/app`) 삭제**. KeymaHub가 쓰는 BLE·캡처 코드는 모두 옮겨졌고, 나머지(리시버 UHID·Inject, Shizuku, IME, evdev 프로브)는 제품에서 제외한 방식. 코드는 git 기록에 남김(커밋 `71410e3` 시점에 있음). CI의 P0 APK 빌드·첨부도 제거.
- 변경: 앱 ID(패키지명) `com.keymahub.app` → **`app.keymahub`**. 코드 패키지는 `com.keymahub` 그대로. 앱 ID가 바뀌어 기존 설치본과는 별개 앱(설정·페어링 다시).
- 변경: 코드 패키지도 `com.keymahub` → **`app.keymahub`** (앱 ID와 같게).
- 실기기: 앱 설치 후 **첫 페어링이 실패**(연결 0.1초 만에 끊김), 페어링 모드를 껐다 켜면 됨 → 연결 즉시 광고를 껐다 켜던 것이 막 만들어진(암호화·페어링 전) 링크를 끊음. 광고 재시작을 연결 3초 뒤로 미룸. 연결·끊김 로그에 사유 코드와 페어링 여부 표시.
