# 다른 기기 제어 중 화면 키보드: 전송한 문자열이 다시 들어가던 것

## 왜
다른 기기를 제어하는 중 폰의 화면 키보드로 카카오톡에 "응 알았어"를 보내고 "아니"를 치면 "응 알았어아니"가 들어감.
폰을 직접 조작할 때는 괜찮음.
- 제어 중에는 키보드가 캡처 창의 숨은 필드에 치고, 바뀔 때마다 그 내용 전체를 접근성으로 앱 입력창에 덮어씀(`TextRelay`).
- 앱이 보낸 뒤 입력창을 비우는 것을 알리지 않으면(텍스트 변경 이벤트 없음) 숨은 필드에 이전 문자열이 남고,
  다음 키에 "이전 문자열 + 새 글자"를 덮어씀. 같은 입력창을 다시 눌러도 다시 읽지 않았음.

## 어떻게
- 덮어쓰기 전마다 입력창을 다시 읽음(`refresh`). 마지막으로 읽거나 보낸 내용(`expected`)과 다르면
  키보드의 이번 변경(끝에서 바뀐 부분)만 실제 내용에 적용(`rebaseTyping`)하고 숨은 필드도 맞춤.
- 같은 창의 버튼(보내기)을 누르거나 Enter 동작 뒤 150ms·600ms에 입력창을 다시 읽어 숨은 필드를 맞춤:
  다음 키 전에 맞춰 두면 한글 첫 글자도 평소처럼 조합됨(키를 칠 때 맞추면 조합이 끊길 수 있음).
- 같은 입력창을 다시 누르면 내용·커서를 다시 읽음.
- 비밀번호 칸은 내용을 읽을 수 없어 그대로.
- 테스트: `TextRebaseTest`.

## 한계
- 실기기 확인 전. 키를 칠 때 맞춘 경우(보낸 뒤 600ms 안에 바로 침 등) 한글 첫 글자 조합이 끊길 수 있음.
