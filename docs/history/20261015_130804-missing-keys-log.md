# PC 제어 중 일부 키(l, p, o, Enter)가 가끔 입력되지 않는 것: 진단 로그 추가

## 왜
PC 제어 중 l, p, o, Enter가 가끔 PC에 입력되지 않는다(항상은 아님). 키 변환표·라우터·대기열에는 특정 키만
다르게 다루는 곳이 없어서, 키 종류보다는 그때의 경로 문제로 보인다. 그런데 키가 빠질 수 있는 경로 중
로그를 남기지 않는 곳이 있어 원인을 가릴 수 없었다:
- 대상 제어 중 폰에 남긴 키(가상 기기·키보드 종류·scan code 없음)는 글자 키면 로그를 남기지 않았다.
- `KeyboardReport`가 받지 않은 누름(이미 눌림, 6개가 이미 눌림)은 조용히 버려졌다.
- 접근성 서비스 스레드가 바빠 키가 늦게 닿는 것(시스템은 약 500ms 뒤 키를 폰에 넘김)은 보이지 않았다.

## 어떻게
- `A11yCapture.unrouted`: 글자 키도 로그(`key left to this device (…): a printing key`). 무엇을 쳤는지는 남기지 않는다.
- `A11yCapture.late`: 대상 제어 중 누름이 200ms 이상 늦게 닿으면 로그(5초에 한 줄).
- `HidSender`: 보고서가 받지 않은 누름의 이유를 로그(`key not sent: still held on the target` / `six keys already held …`).
- 테스트: `KeyboardReport.isFull`·`isHeld`.

## 한계
원인을 고치지는 않는다. 다음에 키가 빠졌을 때 로그로 경로를 가린 뒤 고친다.
