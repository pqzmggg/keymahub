# 입력 경로 지연 줄이기: 마우스 즉시 전달, LE 2M PHY, 스레드 우선순위

- 왜: 표준 API만으로 줄일 수 있는 지연이 남아 있었음.
  - 포인터 캡처한 마우스 이동은 화면 프레임마다 묶여서 옴(8~16ms, `historySize`로 묶인 것을 합치던 이유).
  - 이동 보고는 첫 움직임도 8ms(`MOTION_MS`) 뒤에 나갔음.
  - 링크가 1M PHY라 패킷당 무선 점유 시간이 2배.
- 어떻게:
  - 캡처 중 `requestUnbufferedDispatch(SOURCE_MOUSE_RELATIVE)`(API 30+): 이벤트를 오는 대로 받음. 묶기는 `HidSender`가 이미 함.
  - `HidSender`: 쉬다가 처음 움직이면 바로 보내고, 그 뒤로만 8ms에 하나로 묶음(초당 최대 125개는 그대로).
  - 호스트에 LE 2M PHY 요청(`setPreferredPhy`, 폰이 지원할 때만). 정하는 건 호스트, 안 되면 1M 그대로. 결과는 로그(`PHY tx/rx`). 2M은 도달 거리가 약간 짧음: 책상 거리에서는 문제 없을 것으로 봄.
  - `hid-sender`·`ble-send` 스레드 우선순위 `THREAD_PRIORITY_DISPLAY`: 백그라운드 작업에 밀리지 않게(일반 앱이 쓰는 범위).
  - 고르지 않은 것: 연결 간격을 표준 밖으로 줄이기, 창(`WINDOW`) 크게 늘리기(스택 큐만 쌓임), 접근성 콜백 스레드 바꾸기(불가).
  - 한계: 실기기 측정 전.
