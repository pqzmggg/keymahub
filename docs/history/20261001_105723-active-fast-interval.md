# 연결 간격: 선택된 대상만 짧게

- 왜: 연결된 호스트 전부에 짧은 연결 간격(`CONNECTION_PRIORITY_HIGH`, 약 11~15ms)을 요청했음. 보낼 게 없어도 링크마다 그 주기로 연결 이벤트가 있고 폰의 무선 하나가 이를 모두(폰에 붙은 블루투스 키보드·마우스 포함) 나눠 쓰므로, 기기가 많을수록 이벤트가 겹쳐 쓰고 있는 대상의 전송이 밀릴 수 있음.
- 어떻게:
  - `BleHid.pace`: 선택된 대상은 `HIGH`, 나머지는 `BALANCED`(약 30~50ms). 링크에 붙을 때, 호스팅이 다시 켜질 때, 대상을 바꿀 때(`select`) 요청.
  - `LOW_POWER`(약 100~125ms) 대신 `BALANCED`를 고른 이유: 새 간격은 요청 후 몇 번의 연결 이벤트 뒤에 적용되므로, 느린 간격일수록 전환 직후 첫 입력이 굼뜸. 그동안에도 입력은 지금 간격으로 그대로 감.
  - 폰 슬롯(대상 없음)으로 가면 모든 링크가 `BALANCED`.
  - 한계: 간격은 요청일 뿐 호스트가 정함. 전환 직후 잠깐(수십~수백 ms)은 이전 간격으로 감. 실기기 측정은 아직.
