# 느린 링크에서 마우스 이동 간격 자동으로 늘리기

## 왜
잘 쓰다가 한 번씩 마우스가 갑자기 천천히 움직이며, 지나온 궤적을 느리게 다시 그린다. 끊김(멈춤)이 아니라 느린 재생.
- 앱 대기열(`ReportQueue`)에서는 이동이 합쳐지므로 밀려도 점프할 뿐 느려지지 않는다. 느린 재생은 이미 블루투스 스택에
  넘긴 보고(합칠 수 없음)가 링크 속도대로 빠지는 것: 링크가 잠깐 느려진 동안(연결 간격 변경, 이어폰·Wi-Fi와 무선 경합, 재전송)
  앱이 설정한 간격(10ms)대로 계속 넘긴 만큼 쌓인다.
- 동시 전송 창(2)은 이를 막지 못할 수 있다: `onNotificationSent`가 무선으로 보낸 뒤가 아니라 스택 큐에 넣은 뒤 오는 스택이면
  확인이 바로 와서 창이 거의 늘 비어 있다.
- 이동 간격을 늘 크게 두면 평소에 덜 부드럽다.

## 어떻게
- `MotionPace`(링크별): 느린 신호가 오면 이동 간격을 2배로(설정 최대까지), 신호가 `RECOVER_MS`(1.5초) 없으면 절반씩 설정값으로 되돌림.
  200ms 안에 겹친 신호는 한 번으로.
- 느린 신호(`BleHid`): 전송 확인이 늦음(보낸 뒤 40ms 또는 연결 간격 3배 이상), 보낼 입력이 앱 대기열에서 그만큼 기다림, 확인을 잃음.
  연결 간격(`onConnectionUpdated`)은 "늦음"의 기준에만 쓰고 하한으로는 쓰지 않는다(연결 이벤트 하나에 보고 여러 개가 들어감).
- `HidSender`는 이동마다 `BleHid.motionMs`로 지금 간격을 읽는다.
- 고급 설정 > 마우스: `느린 링크에서 자동으로 늦추기`(기본 켬), `늦출 때 최대 간격`(기본 40ms, 15~100). 6개 언어.
- 로그: `mouse motion to … every N ms for now (이유)` / `… at the set interval again`.
- 테스트: `MotionPaceTest`, `TuningTest` 기본값·범위.

## 한계
- 이미 스택에 쌓인 것은 빼낼 수 없다: 늦추면 더 쌓이지 않고 빨리 풀릴 뿐이다.
- 스택이 확인을 바로 주고 링크가 느려져도 앱에 아무 신호가 없으면 동작하지 않는다. 그러면 증상이 생겨도 위 로그가 없다
  (그때는 이동 간격 자체를 늘리거나 다른 신호를 찾아야 함). 실기기 확인 전.
