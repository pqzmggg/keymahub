# 키보드·마우스가 연결되면 호스팅 자동으로 켜기

## 왜
책상에 앉아 키보드·마우스를 켜면 호스팅도 켜졌으면 함. 지금은 앱을 열거나 바로가기·루틴으로 켜야 한다.

## 어떻게
- 설정 > 동작 > `자동으로 호스팅 켜기`: 끔(기본) / 키보드나 마우스가 연결되면 / 고른 키보드나 마우스가 연결되면.
  - 고르기: 지금 연결된 키보드·마우스와 전에 고른 기기(연결 안 됨 표시)를 체크. Android 입력 기기에는 블루투스 주소가 없어
    `InputDevice.descriptor`(다시 연결해도, 재부팅해도 같음)로 알아보고, 이름은 연결 안 됐을 때 보여 주려고 같이 저장.
  - 키보드·마우스 기준은 홈 안내와 같음(외부, 가상 아님, 글자 키보드 또는 마우스). 이어폰·리모컨의 미디어 키는 빠짐.
  - `연결이 끊기면 끄기`(기본 끔): 세는 기기가 하나도 없이 10초가 지나면 끔. 블루투스 마우스는 쉬면 연결을 끊기도 해서 기본은 끔.
  - 접근성 서비스가 꺼져 있으면 항목 아래에 안내.
- 감지는 접근성 서비스(`AutoHostingWatcher`)에서: 켜져 있으면 앱을 닫아도 살아 있다. 블루투스·USB 모두.
- 연결된 "변화"만 센다(`AutoHostingRule`): 직전 기기 목록을 지금 설정으로 보고 새로 들어온 것만. 그래서
  - 서비스가 처음 볼 때(업데이트 후 등), 설정을 바꿀 때는 켜지 않는다.
  - 직접 끈 뒤 기기가 연결된 채로 있으면 다시 켜지 않고, 끊겼다 다시 연결되면 켠다.
- 켜기 전에 바로가기와 같은 확인(`HubService.startProblem`, 바로가기에서 옮김). 백그라운드 시작이 거부되면 알림으로
  "탭해서 호스팅 켜기"(`HostingShortcutActivity`)를 띄운다.
- 홈 호스팅 카드: 자동으로 켜졌으면 `○○ 연결로 자동으로 켜짐`.
- 6개 언어. 테스트: `AutoHostingTest`(규칙, 저장 형식).

## 한계
- 접근성 서비스에서 포그라운드 서비스를 바로 시작할 수 있는지는 실기기 확인 전(안 되면 알림으로 대신).
- 고를 기기는 한 번 연결해 둬야 목록에 나온다.
