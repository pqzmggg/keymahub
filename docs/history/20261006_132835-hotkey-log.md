# 단축키 전환 결과·프로필 변경·대상 끊김을 로그로 남김

## 왜
PC 제어 중 점심 동안 PC가 절전에 들어갔다가 깨운 뒤 단축키로 PC 전환이 안 됐다는 보고(0.8.4).
로그:

- 13:04:19 PC 끊김(절전) → 앱은 폰으로 돌아감(로그 없음)
- 13:21:33 다른 대상(폰) 다시 연결, 13:22:02 PC 다시 연결(`ready (restored)`), 13:22:24·13:22:32 PC가 HID를 두 번 다시 읽음
- 13:22:50 `screen cover: on` + `pointer captured`: 어떤 대상으로든 전환은 한 번 일어남. 그런데 어느 대상인지는 남지 않음
- 그 뒤 PC로 보낸 입력 흔적(점심 전엔 잦던 `unconfirmed`)이 없음

단축키가 안 먹은 경우(조합 불일치, 대상 미연결, 슬롯에 기기 없음), 프로필 자동 변경(연결된 기기에 따라 바뀌며
단축키 배치가 달라짐), 대상이 끊겨 폰으로 돌아감 — 모두 로그에 남지 않아 원인을 가릴 수 없었다.

## 어떻게
`HubService`에서:
- 전환마다 `control: <이름> (slot N, profile p)` / `control: this device`
- 단축키가 대상에 닿지 못하면 `hotkey of slot N: <이름> not connected` 또는 `no device on it` (프로필·연결된 기기 포함)
- 숫자 키를 단축키와 다른 보조키(Shift만은 타자라서 제외)로 누르면 `not a hotkey: …` (보조키가 눌린 채 남은 경우를 잡음)
- 프로필이 바뀌면 `profile … active, connected: …`
- 제어 중인 대상이 끊기면 `<이름> went away while in control: back to this device`

## 한계
원인 수정이 아니라 진단. #112의 전송 로그(`input to`, `stuck`, `dropped`)와 함께 다음 발생 때 원인을 가린다.
