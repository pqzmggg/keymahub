# 밀림 회귀 수정: 연결 간격 전환 되돌리기, 확인 대기 250ms 복원

- 왜: #103~#105 배포 후 지연이 심해짐. 한번 밀리면 이동 합치기가 있는데도 쉽게 회복되지 않고, 시간이 지나야 풀림.
  - 앱 대기열(`ReportQueue`)에서는 밀린 이동이 합쳐지므로 밀림이 쌓이지 않음. 오래 남는 밀림은 이미 블루투스 스택에 넘어가 합칠 수 없는 보고서가 링크 속도대로 빠지는 것.
  - #103의 두 변경이 스택으로 넘기는 양을 늘렸음:
    - 대상 전환마다 연결 간격을 바꿈(선택 대상만 짧게): 호스트가 적용할 때까지(무시하면 계속) 링크가 느린데 입력은 그대로 들어와 스택에 쌓임.
    - 확인 대기 60ms: 느린 링크에서는 정상 확인도 그보다 늦어, 잃은 것으로 보고 더 보냄 → 창(3개)을 넘어 스택에 쌓임. 늦게 온 확인은 0에서 멈춰 그 뒤로도 창이 넓어진 채로 감.
- 어떻게:
  - 링크를 붙잡는 동안 모든 링크에 짧은 간격(`HIGH`)을 한 번 요청하고 바꾸지 않음(#103 이전과 같음). 여러 기기의 무선 경합 우려는 측정된 문제가 아니었고, 밀림은 실제 문제.
  - `IN_FLIGHT_TIMEOUT_MS` 60 → 250ms(#103 이전 값). 확인 누락은 드묾. 일어나면 로그에 남음.
  - #104(마우스 즉시 전달, 첫 이동 바로 전송, 2M PHY, 스레드 우선순위)는 유지. 보내는 양의 상한(8ms에 하나)은 그대로라 밀림의 원인은 아님.
  - 한계: 실기기 확인 전. 그래도 밀리면 다음 후보는 2M PHY(재전송), 그다음 이동 보고 간격(8ms → 링크 간격에 맞춰 늘리기).
